외부 시스템 연동 — EDI · API

운영사는 시스템 밖의 상대(쇼핑몰, 창고, 운송사, 회계)와 정해진 서식의 문서를 주고받는다 — 프로그램끼리 정해진 규칙으로 데이터를 주고받는 연결 창구가 API, 회사 사이 문서를 정해진 서식으로 주고받는 방식이 EDI(전자 문서 교환)이다.

처음이라면 — 이 페이지가 전제하는 말

시스템 셋 — OMS(주문 관리 시스템)은 주문을 받아 어느 창고에서 내보낼지 정하고, 주문의 상태를 끝까지 지켜보는 프로그램이다. WMS(창고 관리 시스템)은 창고 안의 입고·보관·피킹·출고 작업을 지시하고 기록하는 프로그램이다. TMS(운송 관리 시스템)은 어느 운송사가 어느 길로 옮길지 정하고 운송 상황을 지켜보는 프로그램이다. → 물류 시스템 지도

시스템 연계 — 시스템끼리 문서를 정해진 순서로 넘겨 주는 연결이다. OMS·WMS·TMS 사이 안의 10단계 릴레이를 다룬다. → OMS → WMS → TMS 연계

주문 상태 — 주문이 접수된 뒤 배송이 끝날 때까지 어디까지 진행됐는지 나타내는 표시다. 이 페이지의 "상태 회신" 문서로 쇼핑몰에 돌아간다. → 주문 한 건의 여정

API(Application Programming Interface) — 프로그램끼리 정해진 규칙으로 데이터를 주고받는 연결 창구다.

EDI(Electronic Data Interchange, 전자 문서 교환) — 회사 사이에 주문·통지 같은 문서를 정해진 서식으로 주고받는 방식이다.

ERP(Enterprise Resource Planning, 전사 자원 관리) — 회사의 회계·구매·재무를 함께 관리하는 프로그램이다. 재고를 돈으로 기록하는 곳이다.

비유 — 은행 이체 · 내가 쓰는 앱이 다른 은행과 약속된 양식으로 돈을 주고받는다. 약속이 어긋나면 이체가 실패하고 다시 시도한다. 다만 맞지 않는 지점이 하나 있다 — 은행 이체는 한 번 실패하면 끝나지만, 물류 문서는 재전송 규칙이 있다.

화살표 라벨 = 상대와 주고받는 문서이고, 그 아래 줄 = 연동 방식(API · EDI · 수기 — 수기는 이메일·전화로 문서를 옮기는 방식)입니다. OMS·회계 ERP는 운영사색, 쇼핑몰은 화주색, 창고 WMS는 창고색, 운송사 TMS는 운송사색입니다. 붉은 줄 = 하루 5건의 전송 실패(고정 시나리오)가 그 단계에서 생겼다는 표시이며, 재전송 규칙은 최대 3회 — 그래도 실패하면 사람에게 알립니다. 수기 연동에서는 다시 보내는 것도 사람이 합니다.

    전제: 하루 주문 20건 기준, 문서 9종(주문당 7종 + 정산·청구는 하루 1건), 상대는 4곳으로 단순화했다. 릴레이는 10단계지만 창고 작업 한 단계는 시스템 안에서 일어나 문서가 오가지 않는다. 전송 실패 5건은 고정 시나리오(같은 설정이면 결과가 항상 같다)이고, 미해결 문서는 다음 날 오전 발견으로 보아 240분을 더해 잰다.

    서식과 순서를 정해 두면 문서가 저절로 흐르지만, 연결이 사람 손을 타면 그만큼 느리고 실패한 문서는 방치된다 — 그래서 재전송 규칙과 '3회 실패 시 사람에게' 기준을 정해 둔다.

    시스템에서는 OMS에서는 상대별 연동 방식(API·EDI)과 문서 서식, 재전송 횟수·간격을 설정으로 갖는다. 이 규칙은 상대와 운영사마다 다르게 설정한다.

    선행: OMS → WMS → TMS 연계 — 시스템 안(안의 3종) 문서 릴레이
