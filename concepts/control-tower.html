컨트롤 타워 — 통합 가시성 · 예외 알림

컨트롤 타워는 여러 창고·운송사의 상황을 한곳에 모아 보고, 정해 놓은 기준에서 벗어난 일(예외)만 골라 알린다.

처음이라면 — 이 페이지가 전제하는 말 3개

시스템 셋 — OMS(주문 관리 시스템)·WMS(창고 관리 시스템)·TMS(운송 관리 시스템)가 각자 맡은 일 → 물류 시스템 지도

시스템 연계 — 주문과 상태가 OMS → WMS → TMS로 넘어가는 일 → OMS → WMS → TMS 연계

주문 상태 — 주문이 접수된 뒤 배송이 끝날 때까지 어디까지 진행됐는지 나타내는 표시다 → 주문 한 건의 여정

컨트롤 타워(control tower) — 여러 창고·운송사의 상황을 한곳에서 모아 보고, 사람이 봐야 할 문제를 골라 알려 주는 시스템이다.

예외(exception) — 정해 놓은 기준에서 벗어난 일이다. 지연·부족·불일치 같은 것이 예외다.

예외 알림 — 예외가 생겼다고 담당자에게 보내는 신호다.

비유 — 병원 중환자실 모니터 · 환자별 수치를 전부 볼 수는 없으니 기준을 벗어난 것만 경보를 냅니다. 다만 모니터는 경보만 울리지만, 물류는 사람이 알림을 끄고 다음 조치까지 정해야 합니다.

알림 목록 — 기준을 넘어 잡힌 것

    놓친 예외 — 기준 밖이지만 실제 문제

      전제: 하루 이벤트 30건(예외 6건), 창고 3곳·운송사 2곳, 화주 1곳으로 뒀습니다. 알림 기준은 지연 시간 하나로 단순화했고, 대응 시작은 "쌓인 알림 순서만큼 늦어진다"로 단순화했습니다.

      알림 기준을 예민하게(지연 30분부터) 잡으면 놓치는 일은 줄지만 사람이 알림에 파묻히고, 둔감하게(4시간부터) 잡으면 편하지만 진짜 문제를 흘린다 — 그래서 기준은 물량·계절에 맞춰 조절하고 예외는 등급을 나눠 받는다.

      시스템에서는 OMS에서는 창고·운송사의 상태·위치 이벤트를 모아 기준(임계값)별로 예외를 만들어 담당자에게 보낸다. 알림 기준과 받는 사람은 운영사마다 다르게 설정한다.

      선행: OMS → WMS → TMS 연계 · 물류 시스템 지도(OMS·WMS·TMS) · 주문 한 건의 여정

      다음(심화): 입고 생애주기 · 문서 흐름 — 상태와 문서가 실제로 흐르는 모습. 이어 2단계 '상태 매핑'이 예정돼 있습니다.
