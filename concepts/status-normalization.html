창고의 세부 작업 상태를 화주에게는 어떻게 보여줄 것인가

상태 매핑 — 창고 작업 상태 → 화주용 주문 상태

창고는 '피킹 지시·피킹 중·검수 보류·포장 완료'처럼 잘게 쪼갠 상태를 쓰지만 화주에게는 통째로 옮기지 않는다 — 상태 매핑으로 몇 개의 알아보기 쉬운 주문 상태로 옮겨 보여준다.

처음이라면 — 이 페이지가 전제하는 말

주문 상태 — 주문이 접수된 뒤 배송이 끝날 때까지 어디까지 진행됐는지 나타내는 표시다. → 주문 한 건의 여정

OMS · WMS — OMS(주문 관리 시스템)는 주문을 받아 어느 창고에서 내보낼지 정하고, 주문의 상태를 끝까지 지켜보는 프로그램이다. WMS(창고 관리 시스템)는 창고 안의 입고·보관·피킹·출고 작업을 지시하고 기록하는 프로그램이다. 창고는 작업이 끝날 때마다 상태를 완료 보고로 OMS에 알린다. → OMS → WMS → TMS 연계

피킹 — 주문에 맞는 물건을 창고 안의 자리에서 골라 내는 일이다. → 창고의 하루

상태 매핑(status mapping) — 창고의 세부 작업 상태를 화주에게 보여 주는 주문 상태로 옮겨 놓은 대응표다.

비유 — 병원 수술 전광판 · 수술실 안에서는 마취·절개·봉합까지 여러 단계가 진행되지만 복도 전광판에는 보호자에게 '수술 중' 하나만 보입니다. 다만 맞지 않는 지점이 하나 있다 — 병원 전광판은 정해진 단계만 보이지만 주문 상태는 운영사가 직접 정의합니다.

주문 1건이 지나는 10단계 — 창고 상태와 화주 화면

매핑 적용
미매핑 상태 처리

전제: 주문 1건·세부 상태 10단계, 화주용 상태는 3개로 단순화했다. 실제 정의는 운영사마다 다르다.

매핑을 정리해 두면 화주는 알아보는 몇 개의 상태만 보고 문의가 줄지만, 매핑에 없는 상태가 나오면 그 순간 화면이 멈추거나 엉뚱한 상태가 보인다 — 그래서 미매핑 상태를 어떻게 처리할지도 규칙으로 정해 둔다.

시스템에서는 OMS에서는 창고가 보내온 상태 코드를 화주용 상태로 바꾸는 대응표를 갖고, 표에 없는 코드의 처리(보류/유지)를 규칙으로 정한다. 대응표는 운영사·화주마다 다르게 설정한다.

선행: OMS → WMS → TMS 연계 — 창고가 상태를 완료 보고로 OMS에 알리는 연결
